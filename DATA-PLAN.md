## Tested sources
### Model inference for explanations (ctx.inference)
**Used by**: createCurio action — generates simple jargon-free answer, category suggestion, why-it-matters, and connections from a raw capture
**Test command**: Design relies on documented ctx.inference.complete JSON generation pattern from SDK; no external HTTP probe needed — inference runs server-side inside the action at runtime. Fallback: if inference fails, save the capture with the raw question and a retry state rather than inventing an answer.
**Sample output**: Expected shape { title, category, simpleAnswer, whyItMatters, connections[] } validated with zod in the action.
**Processing**: User's raw capture text is the only input; category constrained to the 8 named categories; answer prompted to be jargon-free and short.

None.

## Long-term data behavior
- **Refresh policy**: No scheduled refresh. Data is user-created only; list queries refetch after every mutation via query invalidation.
- **Growth**: One row per captured curiosity; library grows unbounded, listed newest-first with category filter and search. Settings is a single row (premium flag, launch checklist state).
- **Ordering**: Curios newest first; Review queue shows unreviewed first, then recent.
- **Time semantics**: created_at stored as timestamp_ms; 'today' for the free-tier 3/day counter computed in the viewer's local timezone from created_at calendar day.

## Imagery
Imagery not needed: captures are the user's own moments (their photos/questions) — seeding stock photos would present fake records as their collection. Visual identity comes from category color-coding, specimen-card layout, and a knowledge-map constellation drawn from the user's real curios, not stock imagery.

## Rejected approaches
- **Tried**: Seeding example curios so the library looks full on first open
  **Why rejected**: Would present invented records as the user's own collection, violating content integrity. Ships with an honest, inviting empty state instead.
- **Tried**: Adding quizzes, streaks, XP, social feed to make it feel 'ultra'
  **Why rejected**: User explicitly excluded these in v0.1. 'Ultra' is delivered as polish, depth of explanation, knowledge map, and release readiness — not gamification.
